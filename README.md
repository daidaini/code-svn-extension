# Code SVN

Code SVN 是 VS Code 的 SVN 工作区扩展。它在源代码管理面板中显示本地变更，支持选择文件提交、更新、撤销、查询文件与目录历史，并可按待提交选择生成 AI 提交信息草稿。

扩展内置 SVN 提交前审查，可按待提交选择查看审查结论，或审查后确认提交。独立的 [SVN 提交前审查 CLI](tools/README.md) 也可按选定路径审查代码变更并输出终端报告或 JSON。

## 安装前准备

- VS Code 1.100 或更新版本。
- SVN 命令行客户端 1.14 或更新版本，并在 VS Code 扩展运行的环境中可用。
- 若要从源码启动调试宿主，还需要 Node.js 22 或更新版本。

Windows 本地工作区使用 Windows 环境中的 SVN。VS Code WSL 工作区使用 WSL 发行版中的 Linux SVN；Windows 安装的 SVN 不会自动供 WSL 工作区使用。

在 VS Code 的集成终端（WSL 工作区请使用 WSL 终端）运行以下命令，确认 SVN 可执行：

```sh
svn --version
```

## 安装 VSIX

取得 `code-svn-extension-0.1.3.vsix` 后，可用以下任一方式安装：

1. 打开 VS Code 扩展视图（`Ctrl+Shift+X`），选择右上角 `…` → **从 VSIX 安装…**，再选择 VSIX 文件。
2. 在终端执行：

   ```sh
   code --install-extension code-svn-extension-0.1.3.vsix
   ```

安装完成后按提示重新加载 VS Code。当前工作区中的 VSIX 文件位于仓库根目录；它是本地打包产物，不随 Git 源码提交。

### 安装到 WSL

1. 先通过 **WSL: Connect to WSL** 连接发行版，并在该窗口打开 WSL 内的 SVN 工作副本。
2. 在这个已连接的 VS Code 窗口中打开扩展视图，执行 **从 VSIX 安装…** 并选择同一个 VSIX。
3. 确认扩展安装在 WSL 发行版一侧，然后重新加载窗口。
4. 在该窗口的 WSL 终端运行 `svn --version`。

扩展按工作区所在环境运行，因此 Windows 与 WSL 的 SVN 安装、可执行文件路径和认证配置彼此独立。

### 从源码调试

在仓库根目录执行：

```sh
npm ci
npm run build
```

用 VS Code 打开仓库，按 `F5` 启动 **调试 Code SVN**。在新开的扩展开发窗口中打开 SVN 工作副本。此方式用于源码调试；普通使用请安装 VSIX。

### 从源码构建 VSIX

以下命令适用于 Linux、WSL 或 macOS 的 shell；可从任意工作目录调用。需要 Node.js 22 或更新版本、npm，以及可下载 `@vscode/vsce` 的网络。

构建过程先编译 TypeScript，再在临时 staging 目录组装 VSIX 所需文件。仓库的 `.gitignore` 忽略 `dist/`，所以不能直接从仓库根目录打包。staging 目录只放扩展清单、README、编译后的 JavaScript、审查提示词和生产依赖；生产依赖放在 `dist/node_modules`，以便编译文件运行时可以解析。`vsce ls` 会在打包前显示实际文件清单。

```sh
./build_version.sh
```

脚本会从自身所在目录定位仓库，安装锁定依赖、编译、列出 staging 包内容并生成 VSIX。输出文件位于仓库根目录。

`package.json` 的 `version` 决定输出文件名，例如 `0.1.3` 会生成 `code-svn-extension-0.1.3.vsix`。打包后可检查包内关键文件：

```sh
unzip -l "code-svn-extension-$(node -p "require('./package.json').version").vsix" \
  | grep -E 'extension/(dist/(extension|review|review-ui)\.js|tools/review_prompt\.md|dist/node_modules/fast-xml-parser/)'
```

## 配置 SVN

扩展默认从工作区环境的 `PATH` 查找 `svn`。若 SVN 不在 `PATH`，在 VS Code 设置中将 **Code SVN: Svn Path**（`codeSvn.svnPath`）设为该环境中的可执行文件完整路径，不要附加命令参数或引号。例如：

```json
{
  "codeSvn.svnPath": "C:\\Program Files\\SlikSvn\\bin\\svn.exe"
}
```

WSL 中可使用类似 `/usr/bin/svn` 的 Linux 路径。设置后执行 **SVN：刷新变更**。若查询失败，运行 **SVN：查看查询日志** 查看 SVN 返回的详细原因。

SVN 认证和证书信任沿用当前工作区环境的 SVN 配置。遇到认证或证书问题时，在同一环境的终端完成配置后再刷新；扩展不会忽略证书检查或自动重试失败的提交。

## 日常使用

### 查看与审阅变更

1. 在 VS Code 中打开 SVN 工作副本的根目录或其中一个子目录。
2. 打开源代码管理面板，Code SVN 会显示该打开范围内的变更；也可运行 **SVN：刷新变更**。
3. 点击变更查看文本差异。属性变化会在属性差异文档中显示；二进制文件会说明内容无法作为文本分析。

一个窗口可打开多个目录。同一工作副本中打开目录的并集构成管理范围，重叠部分只显示一次；不同工作副本会分别显示、分别提交。未打开的兄弟目录不会自动加入管理范围。

### 添加并选择提交内容

1. 对于“未跟踪”文件，先使用该行的 **添加到 SVN** 操作，或运行 **SVN：添加到版本控制**。这一步只将文件加入版本控制，不会选择或提交它。
2. 对准备提交的变更，使用资源行的 **加入待提交** 操作，或运行 **SVN：加入待提交**。新发现的变更默认未选中。
3. 查看“待提交”分组及明确标出的“必需提交依赖”。例如，选择新文件时，新增父目录会作为依赖一起提交；依赖超出当前打开范围时，扩展会停止操作并提示扩大工作区范围。
4. 在对应工作副本的源代码管理输入框填写提交信息，然后点击提交按钮，或运行 **SVN：提交待提交文件**。

首版按完整文件选择提交，不支持按行或代码块提交。目录属性可以单独提交；整体目录删除作为一项包含其后代的操作展示。SVN 已记录的移动或复制关系会作为相关变更和依赖处理。

多工作副本时，各自拥有独立的待提交选择和提交信息。通过命令面板提交时，选择目标工作副本。提交失败会保留选择和输入；成功后才清理已提交项目。

### 更新与撤销

- 运行 **SVN：更新管理范围**，或点击 SCM 标题栏的更新按钮。多工作副本时选择要更新的副本；扩展只更新该副本当前打开目录的范围。
- 对已跟踪的变更运行 **SVN：撤销本地变更**，并在确认窗口检查操作范围。未跟踪文件不会因撤销操作而被删除；撤销“添加”会取消版本控制计划并保留本地文件。
- 冲突会在变更列表中标明，冲突项目不能加入待提交或提交。请用现有工具解决冲突、按 SVN 要求标记为已解决，再刷新并重新选择。

### 查看历史

在资源管理器或源代码管理的文件、目录上右键，选择 **SVN：查看历史**。历史从新到旧显示，每批 50 条，可继续加载更早记录。选择一条修订后，可查看与当前文件或目录相关的变更；选择变更项可打开该修订前后的差异。

文件历史中的每条修订旁提供两个按钮（鼠标悬停可查看说明）：

- **与另一修订比较**：选定第一条修订后，再从历史列表选择另一条；可搜索修订号或继续加载更早记录，按 Esc 取消。
- **与最新版本（HEAD）比较**：直接比较该修订与服务器当前最新版本，无需更新工作副本。

版本对比左侧为较早修订、右侧为较新修订，标题显示实际修订号。两侧均读取服务器内容，支持追溯复制、移动前的文件路径，不包含本地未提交修改。属性变化单独展示，二进制文件只显示提示。

历史查询读取服务器记录，不要求工作副本先更新。服务器认证、证书或网络失败会显示错误与相应处理提示，不会显示成空历史。

## AI 提交信息草稿

AI 功能可选。先在 VS Code 设置中配置一个 OpenAI 兼容 Chat Completions 服务：

```json
{
  "codeSvn.ai.baseUrl": "https://api.openai.com/v1",
  "codeSvn.ai.model": "gpt-4o-mini",
  "codeSvn.ai.timeoutSeconds": 60
}
```

`baseUrl` 填服务的 API Base URL，不要在末尾附加 `/chat/completions`。然后运行 **SVN：配置 AI API Key** 输入密钥。密钥保存在 VS Code SecretStorage，不要写进设置文件或提交信息。

使用步骤：

1. 先按上面的步骤选择待提交变更。
2. 点击 SCM 标题栏的生成按钮，或运行 **SVN：生成提交信息草稿**。
3. 审阅并修改生成结果，再手动提交。扩展不会自动提交。

请求只包含本次待提交选择及其依赖的差异和属性变化。二进制文件只提供路径和变更类型，不发送文件内容；发送请求前会提示其内容未分析。一次请求最多 60,000 个字符，超限时会停止并提示缩小选择，不会截断或拆成多次请求。冲突、符号链接等无法完整描述的选择会被拒绝。

若输入框已有提交信息，生成前会询问是否替换。若生成期间选择或内容变化，结果不会填入；填入后若相关选择或内容变化，草稿会被标为过期。提交过期草稿时需要再次明确确认。取消、超时或服务错误会保留原提交信息，由用户决定是否重试。

## SVN 提交前审查

审查复用上述 AI 服务设置和 SecretStorage 密钥，提示词来自扩展内置的 `tools/review_prompt.md`。先按日常提交步骤加入待提交文件，再运行 **SVN：审查待提交** 查看结果，或运行 **SVN：审查并提交** 进入审查后的确认流程。结果显示在源代码管理面板下的「SVN 审查结果」视图中；点击问题可查看审查时的只读代码快照。

无问题时仍需明确确认提交；发现问题或审查不完整时，需要选择对应的继续提交确认。取消、配置或服务错误、过期结果都不会提交。审查并提交会在最终确认后重新检查提交选择、内容、管理范围、提交信息及 AI 配置。审查只读取变更，不修改代码或提交信息；普通的 **SVN：提交待提交文件** 命令仍保留。

## 常用命令

| 命令 | 用途 |
| --- | --- |
| SVN：刷新变更 | 重新查询当前打开范围 |
| SVN：添加到版本控制 | 将未跟踪项目加入 SVN |
| SVN：加入待提交 / 移出待提交 | 调整本次提交选择 |
| SVN：提交待提交文件 | 提交所选内容 |
| SVN：更新管理范围 | 更新所选工作副本的打开范围 |
| SVN：撤销本地变更 | 确认后撤销已跟踪的本地变更 |
| SVN：查看历史 | 查看资源的服务器历史 |
| SVN：生成提交信息草稿 | 用所选差异生成 AI 草稿 |
| SVN：审查待提交 | 审查当前选择并显示结果 |
| SVN：审查并提交 | 审查当前选择，再根据结果确认提交 |
| SVN：查看审查结果 | 打开最近一次审查报告 |
| SVN：配置 AI API Key | 安全保存或清除模型服务密钥 |
| SVN：查看查询日志 | 查看 SVN 查询与错误详情 |

# Code SVN

VS Code SVN 扩展。目前完成任务 01–12：查看打开目录内的 SVN 本地状态与差异，多根工作区、显式添加、
选择文件及其新增父目录依赖提交、撤销、范围更新与冲突展示、文件与目录历史及历史差异，
以及普通文本修改的 AI 提交信息草稿生成。
输入完整性（属性、二进制、新增与超限）和草稿过期生命周期将在任务 13、14 扩展，安装包与双环境验收属于任务 15。

## 开发与运行

1. 安装 Node.js 22 或更新版本、VS Code 1.100 或更新版本，以及 SVN 1.14 CLI。
2. 执行 `npm ci`，再执行 `npm run build`。
3. 在 VS Code 中打开本项目，按 F5 启动「调试 Code SVN」。
4. 在新开的扩展开发窗口中打开 SVN 工作副本或其中一个子目录。
5. 打开源代码管理面板查看中文状态分组。命令面板执行「SVN：刷新变更」，或点击 SVN 面板刷新按钮。

通过「文件 → 将文件夹添加到工作区」打开多个目录。不同工作副本分别显示；
同一工作副本的多个目录合并为一个管理项，重叠路径只显示一次。
从工作区移除目录后，其不再属于打开范围的变更会自动移除。

点击 SCM 中的变更查看本地差异。文本文件在差异编辑器中对照 BASE 与当前内容，
文件和目录属性变化在独立文档中呈现；同时改变内容和属性时，两种视图都保留。
新增、删除按 SVN 状态展示，未跟踪文件直接查看本地内容，二进制内容明确提示不可分析。
符号链接只展示链接目标，避免读取目标文件正文。再次点击会更新已打开的差异。

通过资源行的「加入待提交」「移出待提交」按钮，或同名命令选择完整文件。
在对应工作副本的 SCM 输入框填写提交信息，再点击提交按钮、按 Ctrl+Enter，
或执行「SVN：提交待提交文件」。多个工作副本分别维护选择和输入；命令面板提交时明确选择一个副本。
当前支持普通版本控制文件的内容与文件属性修改，以及新增文件和普通新增目录。选中文件有未保存内容时会提示保存；取消则停止，冲突也会阻止提交。

未跟踪项须先通过资源行按钮或「SVN：添加到版本控制」命令显式添加到 SVN，再加入待提交；添加成功不会自动选择或提交。
新增目录只添加目录自身，不递归添加子项。多层新目录可逐层添加，然后添加需要的文件。
选择新文件时，所需新增父目录自动展示为「必需提交依赖」，随选定文件一起提交；移出子项后只移除不再需要的依赖。
新增目录也可显式加入待提交，提交使用非递归深度，不夹带未选兄弟文件或子项。
依赖超出打开范围时，添加或选择、提交均会停止并解释原因；请把所需父目录加入工作区再操作。
提交失败保留选择和输入；只有确认产生修订并刷新后才清理。若已产生修订但刷新失败，请先核对仓库结果，勿重复提交。
选择与输入仅保留在当前扩展会话中，重载窗口或宿主重启后需要重新选择。

通过 SCM 标题栏的更新按钮或「SVN：更新管理范围」命令同步远端变更。
多工作副本时，命令面板要求选择一个副本；只更新该副本当前打开目录的并集，
重叠目录去重，不更新未打开区域，不接管 externals 或嵌套工作副本，也不扩展稀疏检出的深度。
更新范围内有未保存内容时会停止，须先保存或自行处理。

更新与提交、添加、撤销共用工作副本写锁，不自动解决冲突或重试提交。
成功或部分应用后失败都会刷新实际状态；仍有变更的选择及提交信息保留，
只有确认已干净的选定路径才移出待提交。更新已执行但刷新失败时会明确提示，旧列表不能视为最新状态。
文本、属性和树冲突以「冲突」展示；已选文件或依赖发生冲突时，所属分组标记「含冲突」，资源行有警告图标及冲突提示。
冲突路径不能选择或提交。请使用工作区环境中已有工具解决冲突并用 SVN 标记为已解决，
再执行「SVN：刷新变更」审阅状态，随后手动选择并提交；插件不代替用户选择解决方式。
认证、证书和网络失败保留 SVN 原始原因，不绕过证书检查；详细同步结果可在「SVN：查看查询日志」查看。

默认调用工作区环境 PATH 中的 `svn`。如果安装在其他位置，在设置中配置
`codeSvn.svnPath` 为可执行文件完整路径，不添加命令参数或引号。例如：

```json
{ "codeSvn.svnPath": "C:\\Program Files\\SlikSvn\\bin\\svn.exe" }
```

扩展采用 workspace 运行方式。VS Code WSL 工作区需要在 WSL 内安装 Linux SVN，
路径也使用该环境路径；目前 WSL 实际运行尚未验收。

## AI 提交信息草稿

先在设置中配置一套 OpenAI 兼容服务：

```json
{
  "codeSvn.ai.baseUrl": "https://api.openai.com/v1",
  "codeSvn.ai.model": "gpt-4o-mini",
  "codeSvn.ai.timeoutSeconds": 60
}
```

再执行「SVN：配置 AI API Key」输入密钥。密钥只保存在 VS Code SecretStorage，不写入设置文件、提交信息
或查询日志；留空回车可清除已保存的密钥。三项配置缺一时生成会给出缺失项并直接结束，不发送请求。

点击源代码管理面板标题栏的生成按钮，或执行「SVN：生成提交信息草稿」。生成与提交共用同一份待提交选择：
空选择不请求；选中文件有未保存内容时先提示保存，取消则停止；同一副本正在生成时再次点击不会重复发送。
一次请求为非流式 Chat Completions，输入只有选中项（含必需提交依赖）的文本差异，路径相对工作副本根，
返回中文短标题及必要要点。输入框已有内容时先确认替换；草稿只填入输入框，仍需用户审阅、修改后手动提交。

当前版本只支持普通文本内容修改。属性变化、新增、删除、目录、冲突、符号链接与二进制内容会逐项列出
并明确拒绝，整次操作不发送请求；属性、二进制与输入超限的完整表达属于任务 13。取消、超时与服务错误
均保留原提交信息，由用户手动重试；请求期间提交选择或内容发生变化时，返回结果不填入输入框，
生成后的草稿过期处理属于任务 14。

## 当前行为

- 展示和写操作限定在打开目录内。同一工作副本的管理范围取打开目录并集，不扩大到未打开的兄弟目录；仅以非递归查询读取祖先节点的提交依赖元数据。
- 每个工作副本拥有独立 SCM 视图、状态列表和错误提示；一个副本失败不会阻止其他副本刷新。
- 展示新增、修改、删除、缺失、未跟踪、属性修改及冲突。
- 不接管嵌套工作副本、目录 externals 或文件 externals；非 SVN 目录不显示 SVN 管理项。
- 文件变化触发刷新，同时每 5 秒检查状态，覆盖外部 SVN 操作。
- 查询失败时显示错误提示和状态栏警告，保留上次成功列表。通过「SVN：查看查询日志」查看原因；不能将失败后的旧列表视为最新状态。
- 状态、差异查询与添加操作超时为 20 秒；添加失败后应刷新核对状态，不自动重试。手动刷新和自动刷新串行执行。
- 同一工作副本写操作互斥。提交和更新不设置强制超时、不自动重试、不自动忽略证书错误；访问失败时在工作区所在环境的终端配置认证与证书信任。

## 验证

`npm run typecheck` 检查 TypeScript；`npm test` 构建并运行集成测试。
测试需要本机安装 SVN、svnadmin 和 VS Code，启动独立的真实 VS Code 窗口，
通过公开命令、SCM 与编辑器可见结果及真实仓库修订断言结果，不调用私有函数。
测试仓库、用户配置和扩展目录全部隔离于 `.test-artifacts/`，结束后清理。

Windows 自动从 PATH 中的 `code.cmd` 找到 VS Code 主程序；其他位置或 Linux
需设置 `VSCODE_EXECUTABLE`。也可设置 `SVN_EXECUTABLE`、`SVNADMIN_EXECUTABLE`。
VS Code 窗口需要可用的桌面会话。测试使用随机端口的本机 Chromium 调试连接。

已通过与未验证的结果见 docs 目录下的任务验证记录（task-01 至 task-12）。
安装包及 Windows/WSL 的完整首版验收属于任务 15。

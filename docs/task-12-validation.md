# 任务 12 验证记录

日期：2026-10-13。

## 实现范围

配置一套 OpenAI 兼容模型服务，对本次提交选择中的普通文本修改生成中文提交信息草稿，填入输入框由用户
审阅、修改后手动提交。本票只交付输入内容不变的正常生成流程；属性、二进制、新增、删除、输入超限与完整
草稿过期生命周期留给任务 13、14，未覆盖的输入一律明确拒绝，不静默发送部分内容。

**配置与密钥。** 新增 `codeSvn.ai.baseUrl`、`codeSvn.ai.model`、`codeSvn.ai.timeoutSeconds`（默认 60 秒）
三项窗口级设置。API Key 通过「SVN：配置 AI API Key」写入 `context.secrets`（VS Code SecretStorage），
不落设置文件、不进查询日志，也不出现在错误提示中；留空回车可清除已保存的密钥。任一配置缺失时提示缺失项
并给出「配置 AI 服务」「设置 API Key」入口，明确说明未发送请求。

**输入边界。** 生成与提交共用同一份提交选择（`CommitSelection.targets`，含必需提交依赖）。空选择不请求。
调用前用与提交相同的 `validate` 检查管理范围、依赖与冲突。选中文件有未保存内容时先提示「保存并生成」，
取消则停止；确认后保存文件再采集差异。逐项读取所选目标的 BASE 与工作内容，只有「普通文本内容修改」进入
输入；属性变化、新增、删除、替换、目录、冲突、符号链接、二进制内容、无文本差异分别按路径和原因列入拒绝
清单，整次操作不发送请求。差异由插件自行按行计算统一 diff（首尾公共行 + 中段 LCS，规模上限 100 万单元，
超限退化为整段替换），路径使用相对工作副本根的 POSIX 风格，避免 SVN 控制台编码影响中文路径。

**请求与结果。** 单次非流式 Chat Completions 请求 `POST {baseUrl}/chat/completions`，
`stream:false`，system 提示要求中文短标题加必要要点、不输出解释和 Markdown 代码块，user 为逐文件的
`### 文件：<相对路径>` 加统一差异。请求期间以 `withProgress` 提供取消入口；同一工作副本再次点击不会重复
发送。取消、超时、HTTP 错误、非 JSON 响应和空草稿都保留原提交信息，只由用户手动重试；错误提示携带原始
状态码与受限长度的服务错误正文（截断 300 字符），不自动重试。

**填入规则。** 提交输入框已有内容时在发送请求前确认替换并展示将被替换的文本；返回结果前重新刷新状态、
校验选择并重新采集差异，选择或内容发生变化、视图已失效时丢弃结果不填入；输入框在生成期间被改动时也不
填入。填入后不提交，提示用户审阅或修改后手动提交。

`src/svn.ts` 的状态标签 `label` 提为共享的 `changeLabel`，变更列表与 AI 拒绝原因使用同一说法。

## 公开入口集成验证

环境：Linux x64、Node.js 24.10.0、SVN 1.14.3、VS Code 1.100.3 开发宿主。测试启动真实 VS Code 桌面窗口，
命令面板、SCM 面板、模态框、进度提示与通知观察结果；模型服务为本机随机端口的可控 HTTP 服务，记录每个进入
的请求。

`test/ai-draft.test.cjs` 的 6 项测试全部通过：

- 空选择与缺少 API Key 各请求 0 次；配置齐全后只发一次请求，捕获的请求体含所选文件的
  `### 文件：中文 空格 @目录/修改 中文.txt` 与 `-initial`/`+第一行改为安装步骤`，不含未选文件路径或内容，
  `stream:false`、`model` 正确、`Authorization: Bearer <密钥>`；草稿填入输入框，仓库修订不变，用户追加
  「- 人工补充要点」后手动提交，仓库日志同时含模型草稿与人工补充。
- 选中文件有未保存内容时弹出保存提示：取消后 0 请求且磁盘内容不变；「保存并生成」后请求使用保存后的内容，
  不再包含旧的 `SAVED`。
- 输入框已有内容时先确认替换：取消则 0 请求且原文保留；确认后草稿替换原文，仍不自动提交。
- 属性变化、二进制（`svn add` 自动写入 `svn:mime-type=application/octet-stream`）与新增文件同时入选时，
  提示逐项列出 `修改 中文.txt：属性变化`、`data.bin：二进制内容`、`新增.txt：已添加` 且未发送请求；
  把新增文件提交后改为普通文本修改，同样入口可正常生成。
- 取消、HTTP 500、超时（`codeSvn.ai.timeoutSeconds: 1`）三种结果都保留原提交信息「原有的提交信息」，
  每次用户操作只对应一次服务端请求，无自动重试；生成中再次点击得到「不会重复请求」提示；随后手动重试成功填入草稿。
- 请求期间移出待提交时，返回结果不填入，提示「生成期间已变化」，输入框保持为空；重新选择后再次生成成功。

完整 `npm test`：**95 项全部通过**（此前 89 项 + 本任务 6 项），日志 `.test-artifacts/task12-full-suite.log`。
`npm run typecheck` 通过。

测试宿主改动：`test/host.cjs` 的快捷键触发前把焦点交还 `.monaco-workbench`，命令面板输入框只取当前可见的
`input:visible`（关闭的输入框会残留在 DOM 中）。原因是本机没有系统密钥环，VS Code 为 SecretStorage 弹出
「Use weaker encryption」提示并抢占焦点，吞掉后续 F1。

本任务的集成测试必须串行运行：同时开两个测试进程会争抢同一个桌面会话的焦点，出现过一次未选文件内容进入
请求的假失败；单独重跑即恢复通过。

## 自查

未使用子代理或 Codex CLI（项目规则：仅在明确要求时调用）。

- 规范：命令与设置标题沿用中文；参数数组调用 SVN，不对模型服务做 shell 拼接；AI 读取为只读，不加写锁，
  与提交共用选择校验入口；密钥不写日志；错误提示给出可操作原因且保留原输入。
- 规格：对照工单验收项，配置、同一选择、单次非流式请求、替换确认、取消/超时/服务错误、未覆盖输入拒绝与
  请求期间选择变化都有公开入口证据。
- 与 ADR 0001 的关系：该 ADR 要求 AI 输入包含文件和目录属性差异。本票按工单拆分先对属性输入明确拒绝，
  不静默发送不完整内容；完整输入由任务 13 落地。这是拆分顺序，不缩减已确认边界。

## 尚未验证

- 真实模型服务兼容性：需要使用者配置一家厂商后验证；可控服务通过不等于真实服务通过（工单第 7 项的
  「配置真实服务后可演示完整文本生成流程」仍未勾选）。
- 代理环境：请求走 Node `fetch`，不读取 `http_proxy`/`https_proxy` 环境变量，也未接入 VS Code 代理设置。
  需要通过代理访问服务的用户可能失败，本机未验证。
- 非 ASCII API Key：HTTP 头要求 ASCII，含中文的密钥会被 `fetch` 拒绝并报为请求失败；未做单独提示。
- 输入超限、属性/二进制/新增等输入的完整表达属于任务 13；生成后草稿过期提示与「明确确认继续使用」属于
  任务 14。本票只实现请求期间的变化检测，不勾选这些项。
- 取消按钮在多条通知堆叠时会被折叠；测试通过 DOM 触发文字按钮「Cancel」，用户可见的展开行为未做专门验证。
- 大文件差异的 LCS 退化分支（超过 100 万单元格）未测试；行尾符-only 变化会被判为「没有文本内容差异」而拒绝，
  未做单独验证。
- Windows 宿主与 WSL 会话下的 SecretStorage（真实密钥环）、通知焦点行为留待任务 15。

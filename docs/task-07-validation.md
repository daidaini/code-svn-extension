# 任务 07 验证记录

日期：2026-10-12。审查基准：`5035269`。实现提交：`a4940e6`。

实现范围：SVN 已记录的移动、重命名与复制。状态解析补充移动关系
（`svn status --xml` 的 `moved-from`/`moved-to`，相对被查询目录，含 `..`，
一次解析为绝对路径）与复制来源（对被删除与被复制条目一次批量 `svn info`，
取复制根的 `copy-from-url`/`copy-from-rev` 及仓库相对路径）。展示上：
移动目标显示「已移动」并注明来源，复制目标显示「已复制」并注明
`^/仓库路径`，复制目录注明整个复制子树随目录一起提交；移动的源删除行注明
「已移动到（随目标一起提交）」。

关键 SVN 语义均先行实证：移动两侧必须一起提交（E200009：both sides of the
move must be committed together），文件与目录皆然；复制单独提交即可；复制
目录提交在仓库端始终递归（SVN 明确警告），复制子树按来源基线内容入库，
子项的内容/属性修改与子项内新增均不被 `--depth empty` 夹带；嵌套复制节点的
复制历史只在复制根上，复制根必为 `item="added"` 条目，故子项基线从最近的
复制祖先来源加相对路径推导；`svn diff` 对移动/复制按 copy-from 比较，
属性比较同样如此，故审阅的内容与属性基线改用复制来源修订号。移动源依赖与
必需父目录依赖统一进入 `必需提交依赖` 分组；移动源不在管理范围时选择被
阻止并说明原因；资源管理器重命名呈现为「本地缺失」+「未跟踪」，`svn add`
后是普通「已添加」（无 copied 标记），不做移动推断；不新增专用操作入口。

任务 07 的 6 项公开流程测试通过（test/recorded-moves.test.cjs）：

- 移动文件：「已移动」分组呈现，源删除作为必需提交依赖；提交后仓库端旧路径
  消失、新路径存在，`svn log -v` 保留 copyfrom-path。
- 移动目录：源目录与受影响子项（含嵌套子目录）以「已删除子项」呈现；
  提交后整个移动关系保留（copyfrom-path 指向原目录）。
- 复制文件与目录：「已复制」分组；复制文件的审阅显示内容（复制来源基线）；
  复制目录递归提交但子项修改不夹带——仓库端保持基线内容，本地子项保持修改。
- 资源管理器重命名：缺失与未跟踪按原状态呈现，无「已移动」分组；显式添加后
  为普通「已添加」，状态无 copied 标记，旧路径仍为 missing，不做推断。
- 移动源超出打开范围：选择被阻止，提示移动源不在当前管理范围；不产生待提交
  选择、不产生修订，仓库端无变化。
- 移动提交不夹带未选无关变更：仓库端无关文件保持原内容，本地保持修改。

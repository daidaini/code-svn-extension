# SVN VS Code 插件首版设计

更新日期：2026-10-12。Q1–Q23 的设计选择均已确认，本文为汇总后的首版规格；整体方案待用户确认后进入实现。

## 目标

独立的 VS Code SVN 插件，用于管理打开的项目，补足用户需要的文件和目录历史查询，并支持 AI 生成提交信息。

## 已确认范围

- 首版同时支持 Windows 本地工作区和通过 VS Code WSL 打开的工作区，分别验收。
- 用户在工作区所在环境安装 SVN 命令行工具；Windows 调用 Windows SVN，WSL 调用 Linux SVN，并提供 SVN 可执行文件路径设置。
- 以 VS Code 源代码管理面板为主要入口，开发独立插件。
- 首版基础功能：变更列表、差异查看、添加到版本控制、撤销本地修改、更新工作副本和选择文件提交。
- 选中的文件整体参与提交；按代码块提交不在首版范围内。
- 目录同样可以参与提交，首版展示文件和目录的新增、修改、删除及 SVN 属性变化。
- 新增父目录列为必需提交依赖；删除目录按整个子树选择并展示受影响子项，不承诺逐子文件选择目录删除。依赖超出管理范围时阻止操作并说明原因。
- 支持打开完整工作副本、其中的子目录，以及多根工作区中的多个 SVN 项目；打开子目录时仅展示、操作打开的目录范围。
- 多个工作副本分别展示、分别提交；首版不自动接管嵌套工作副本或 svn:externals。
- 同一工作副本的多个打开目录合并展示并去重，管理范围取打开目录的并集；非 SVN 目录不显示 SVN 管理项。
- 未跟踪文件必须先执行添加到 SVN，才能加入待提交；添加与提交保持两个明确步骤。
- 首版正确展示已通过 SVN 完成的移动、重命名和复制，暂不提供专门操作入口，不自动推断资源管理器重命名应视为 SVN 移动。
- 变更列表提供加入本次提交和移出本次提交操作，提交与 AI 生成共用同一份提交选择；界面称为“待提交”。
- 新发现的变更默认未选中；没有提交选择时不能提交或生成 AI 草稿。
- 文件和目录历史提供提交列表，以及作者、时间、提交信息、变更文件和对应差异；目录历史包含子项。
- 历史列表显示修订号；文件历史只展示该文件的变化，目录历史只展示该目录范围内的变化，差异比较对应提交前后的内容。
- 文件和目录右键菜单提供历史入口；最新优先，每次加载 50 条，提供加载更多，不在首版加入复杂筛选。
- 历史查询包含服务器最新记录，沿 SVN 记录的复制或移动关系追溯旧路径；只展示所查询对象的历史变化，不混入同一修订中无关对象的变化。
- 点击历史记录展示变更列表，再通过 VS Code 差异编辑器查看提交前后的内容。
- AI 仅依据本次提交选择中的变更差异生成提交信息草稿，包含文件和目录属性差异，填入提交输入框，由用户修改并手动提交。
- 点击 AI 生成时，将选定差异发送到配置的模型服务；没有选择文件时提示用户选择。
- 首版维护一套有效的模型服务配置，包含 Base URL、模型名称和 API Key，使用 OpenAI 兼容格式；API Key 使用 VS Code SecretStorage。
- AI 草稿默认使用中文纯文本，优先输出不超过 50 字的一行简短标题，并以「[修复]」「[需求]」「[重构]」「[优化]」之一开头；无法判断时使用「[变更]」。只有一行无法说明清楚时才附变更要点。
- 提交输入框已有内容时，AI 生成结果须经用户确认后才能替换。
- 提交或 AI 生成前，所选文件有未保存内容时提示保存这些文件；保存后继续，取消则停止当前操作。
- 展示冲突并阻止提交范围内存在冲突的提交；用户通过 VS Code 或外部工具解决并标记后刷新。首版不开发独立合并界面，不自动更新或解决冲突。
- AI 对二进制文件仅接收路径与变更类型，明确说明未分析其内容；文本差异超限时提示缩小提交选择，不静默截断，不进行多请求分段总结。
- AI 请求过程中提交选择或相关内容发生变化时，返回结果视为过期，不填入提交输入框，并提示重新生成。
- AI 草稿生成后相关内容再次变化时，提示草稿可能过期；用户重新生成或明确确认继续使用。
- SVN 优先使用工作区所在环境已有的认证配置；缺少认证或证书信任时引导用户在同一环境终端完成配置。首版不另做 SVN 账号管理，不自动忽略证书错误。
- 撤销前必须确认操作范围，尤其是目录及其子项，明确提示将丢弃哪些本地修改；不顺带删除未跟踪文件，取消加入版本控制时保留本地文件。
- 自动刷新本地变更，同时提供手动刷新；同一工作副本执行写操作时禁用其他写操作。
- 历史查询和 AI 请求可取消；提交不提供强制中断或自动重试。
- 操作失败时保留提交选择和输入信息；确认提交成功后清理已提交项并刷新。首版不主动跨窗口重启保存提交选择。
- 模型调用采用 Chat Completions 接口，单次请求、非流式完整返回草稿；使用配置的 API Base URL、模型与 API Key，支持超时和取消，失败后由用户手动重试。
- 交付源码、可安装的 .vsix、中文界面和使用说明；Windows 与 WSL 分别进行实际操作验收。

## 主要使用流程

### 选择提交与 AI 草稿

1. 打开项目，展示管理范围内的 SVN 变更，新发现的变更默认未选择。
2. 未跟踪文件先添加到 SVN；用户加入待提交项，查看新增父目录依赖或整体目录删除范围。
3. 点击生成提交信息，先检查选择、必需依赖、冲突和未保存文件，再采集本次差异。
4. 文本差异超限时停止并提示缩小选择；二进制仅提供路径和状态，明确未分析内容。
5. 请求完成时核对选择与相关内容；过期结果不填入，输入框已有内容则确认替换。
6. 用户审阅或修改草稿后点击提交；相关内容变化时按过期规则重新生成或确认继续使用，并重新检查提交条件。
7. 确认产生提交后清理已提交项并刷新；失败则保留选择和输入信息，不自动重试。

### 文件或目录历史

1. 从文件或目录右键菜单打开历史，从服务器最新记录开始加载。
2. 最新优先，每批 50 条，通过加载更多获取更早记录，包括 SVN 保留的复制或移动前历史。
3. 选择修订记录，查看所查询对象对应的变更路径和提交信息。
4. 选择变更项，在 VS Code 差异编辑器中查看这次提交前后的变化。

## 实现组织

以下为落实已确认方案的实现安排，不增加产品功能：

- 使用 TypeScript 开发 workspace 扩展，主入口负责 VS Code 命令、源代码管理面板和历史视图。
- SVN 调用负责当前环境的可执行文件、参数传递、状态/历史数据解析、差异读取及写操作结果；避免通过 shell 拼接用户路径。
- 工作副本与提交选择负责打开范围、去重、必需依赖及写操作互斥。
- AI 调用负责一套有效配置、SecretStorage、差异输入、取消/超时及草稿过期检查。
- 历史视图负责按需加载和对象历史，历史内容交给 VS Code 差异编辑器展示。

## SVN 行为核对

使用本机 SVN 1.14.2、隔离配置的 file:/// 临时测试仓库验证以下行为；专用测试目录已清理：

- 新增文件所需父目录尚未提交时，单独提交子文件失败；显式列出新增父目录和所选文件，并采用非递归目标深度，可保留未选兄弟文件的新增状态。
- 显式目录目标采用非递归目标深度，可只提交该目录属性；删除目录即使采用该深度仍删除整个子树。
- 删除目录下单个后代的提交可能返回退出码 0 而未产生修订，成功判断还需确认提交输出和刷新后的状态。
- 未加入版本控制的文件不提供普通 SVN 文本差异；加入后新增文本以全行新增呈现。
- SVN 二进制差异不提供内容文本，属性差异有独立区段，不能忽略目录或文件属性变化。

以上是已核对的实现约束，尚不表示插件已实现或完成平台验收。

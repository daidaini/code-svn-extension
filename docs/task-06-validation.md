实现范围：目录属性变更与整体目录删除。目录属性行（`item="normal"` 且
`props="modified"` 的目录）可加入待提交；提交仍使用 `--depth empty`，只发送
目录自身属性，不夹带子文件的内容或属性。`svn rm` 的目录以整个子树为一次操作：
状态查询为每个被删除条目补充 `svn info` 的 `kind`（一次批量调用），目录根显示为
「已删除（整个目录）」并注明受影响子项数量，子项归入「已删除子项」分组展示；
子项不可单独选择，选择列表排除子项，资源行点击子项会提示改选目录本身。
`svn commit --depth empty 目录@` 提交整个子树删除（已实证：仓库端子树全部消失，
返回修订号）。文件删除仍然关闭，`删除操作尚未开放` 提示不变。

关键 SVN 语义均先行实证：被删除路径（含中文、空格、`@` 路径）的 `svn info --xml`
返回 `kind`；被调度删除的目录 `proplist` 报 W200005/E200009，由既有
`noPropertyTarget` 处理为空属性表；`svn rm` 遇未版本控制或嵌套工作副本子项直接
失败，故被删除子树的状态列表不存在未接管对象，展示不会误报。kind 未知时保守
按文件处理：目录删除被阻止、显示不聚合，不猜测整体子树范围。

### Standards

硬性违规：未发现；差异符合 docs/design.md 与 ADR 0003 边界。判断性提示三项：
`showChanges` 的展示逻辑与选择状态耦合（可能的 Feature Envy）、整体删除的
过滤/提示/展示分布在不同函数（可能的 Shotgun Surgery）、`kind` 以字符串字面量
判断（可能的 Primitive Obsession）。均为提示；展示与选择处理沿用既有架构，
本票不做重构。

### Spec

发现三项：(1) 已选删除目录提交前不检查其子项的未保存文档——保存检查的意义是
把未保存编辑纳入提交，删除操作不捕获任何内容，视为不适用并在此记录；
(2) `svn info` 失败导致 kind 未知时界面不聚合展示——提交侧已按"范围不明时停止"
保守阻止，记录为已知保守行为；(3) 目录属性隔离测试未覆盖子文件属性变更未被
夹带——已采纳，测试补强为同时断言子文件属性在仓库端不存在（W200017）。
无范围扩张。
